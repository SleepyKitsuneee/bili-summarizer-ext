# B站视频总结助手 · 浏览器插件版（Edge 扩展）

> **这是本项目的主要维护版本。**
> 功能更新、格式调整、提示词优化都在这里进行。
> 另有一个**桌面 exe 版**（归档/备用）：https://github.com/SleepyKitsuneee/bili-summarizer-exe

给一个 B 站视频链接，自动：下载 → 本地合流 → 静默上传千问 → 输出结构化总结。

全程**不操控你的浏览器**：不切标签页、不抢焦点、不弹窗，你在别的页面照常浏览，总结在侧边栏里自己长出来。

---

## 它能做什么

1. **下载**：360P + 64K 音质（省流量、够看够听），走你自己的 B 站登录态
2. **本地合流**：浏览器内用 ffmpeg.wasm 把视频流和音频流合成一个 mp4（`-c copy`，不转码）
3. **静默上传**：合成好的视频直接送进你已登录的千问页面，由千问自己完成附件上传
4. **结构化总结**：用能读视频的 omni 模型输出固定结构的 JSON（结论、核心要点、争议或不足、分段摘要、关键词）
5. **多标签页并行**：每个标签页独立任务，切来切去互不干扰，各自的总结互不覆盖
6. **完整运行日志**：侧边栏「日志」里可查看/复制全流程记录，排错不用猜

## 安装

> 未上架 Edge 商店，需要用**开发者模式**加载（免费，无需开发者账号）。

1. 下载本仓库（或直接下载 Release 里的 zip 并解压）
2. Edge 打开 `edge://extensions`
3. 打开右下角（或左侧）的 **开发人员模式**
4. 点 **加载解压缩的扩展** → 选择本目录（含 `manifest.json` 的那一层）
5. 打开 `https://chat.qwen.ai/` 用你自己的账号登录一次（登录态长期有效）
6. 打开任意 B 站视频页 → 点工具栏插件图标打开侧边栏 → 点「开始总结」

### 自己打 zip 给别人

把本目录（排除 `test/`、`test-assets/` 这两个开发用目录）打包成 zip 即可，约 10MB：

```
bili-summarizer-ext/
├── manifest.json
├── background.js          # 任务编排
├── content/               # 页面驱动 + 补丁
├── lib/                   # B站接口 / 千问接口 / CDP / base64
├── offscreen/             # ffmpeg.wasm 宿主
├── sidepanel/             # 侧边栏界面
├── vendor/                # ffmpeg 引擎
├── icons/
└── summary_schema.json    # 总结格式契约
```

分发时提醒对方：**必须先解压成文件夹再加载**，Edge 不允许直接安装 zip。

## 设置（侧边栏内）

| 项 | 说明 |
|---|---|
| **模型** | 默认 `Qwen3.8-Omni-Flash`。点「读取列表」可从已打开的千问页实时拉取可选模型。**必须选 omni 系列**，非 omni 模型读视频会张冠李戴 |
| **提示词前置说明** | 最终提示词 = 这段说明 + 固定 JSON 结构。改完点「保存」 |
| **日志** | 默认折叠。展开可查看/复制/清空完整流程日志 |

> 注意：如果你之前保存过自定义提示词，新版本的默认提示词**不会自动覆盖**它（这是设计如此）。想拿新版默认就点「恢复默认」再「保存」。

## 架构

```
B站视频页
   │ 点击开始总结
   ▼
background.js（任务编排，每个标签页独立）
   ├─ lib/bilibili.js   取视频信息 + DASH 流 + 下载
   ├─ offscreen/        ffmpeg.wasm 合流（二进制不经后台，由页面自取）
   ├─ lib/cdp.js        chrome.debugger 激活千问页（见下方说明）
   ├─ content/qwen-driver.js   驱动千问页面：选模型 → 喂附件 → 发送
   ├─ lib/qwen.js       轮询答案（只读接口）
   └─ sidepanel/        界面：进度 / 总结 / 历史 / 设置 / 日志
```

几个关键设计：

- **二进制走 base64 分块**：扩展消息是 JSON 序列化，直接传 `Uint8Array` 会丢字节
- **延时用 MessageChannel**：后台标签页的 `setTimeout` 会被浏览器节流到最慢 1 次/分钟，会让流程看起来"卡死"
- **debugger 权限的用途**：标签页在后台会被浏览器节流，千问页面的上传管线会冻结。插件用 CDP（DevTools 同一套协议）把页面置为 active，从而**在不切换标签页、不抢焦点的前提下**让页面 JS 全速运行。附加期间窗口顶部会有一条系统提示条，发送完成后立即解除
- **回执走存储而非内存**：MV3 后台脚本随时可能被浏览器回收，因此"发送成功"的回执落在 `storage.session`，后台重启后任务能自动续上

## 权限说明

| 权限 | 用途 |
|---|---|
| `storage` / `unlimitedStorage` | 保存历史、设置、日志 |
| `sidePanel` | 侧边栏界面 |
| `offscreen` | 宿主 ffmpeg.wasm 做合流 |
| `scripting` / `tabs` | 按需注入/驱动千问页面 |
| `declarativeNetRequestWithHostAccess` | 给 B 站 CDN 请求补 Referer（防盗链） |
| `debugger` | 后台静默激活千问页，避免浏览器节流导致上传卡住 |

## 已知限制

- **依赖千问网页端**：千问改版会让页面选择器失效，届时需要适配（有完整日志便于定位）
- **需要开发者模式**：未上架商店，分发靠解压加载
- **需要你自己的千问登录态**：插件不含任何密钥，也不上传数据到第三方（视频只在本地与你自己的千问账号之间流转）
- 上传阶段若页面被浏览器冻结，插件会自动重试激活；仍失败时日志里会写明原因
